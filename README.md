# ActiveAdminTheme

A dense desktop theme and a set of shared components for [ActiveAdmin](https://github.com/activeadmin/activeadmin) 4.

ActiveAdmin 4 keeps its menu in a left sidebar and gives breadcrumbs and titles a lot of room. That works on mobile but wastes width on a laptop with a large table and many filters. This theme keeps the compact desktop layout of theme 3 and keeps ActiveAdmin 4's mobile support:

- **Desktop** (768px and wider): a horizontal top menu, compact breadcrumbs and title, filters left of the table (collapsible).
- **Mobile** (narrower than 768px): the menu opens in a drawer, filters sit above the table, forms and show pages use the full width.
- Index tables scroll sideways when they are wider than the screen, and cells stay on one line.
- Theme 3 colors, density, and typography on top of ActiveAdmin 4's own dark mode.

Theme 4 needs ActiveAdmin 4 (`>= 4.0.0.beta23`) and Ruby 3.3 or newer. For ActiveAdmin 3, use theme 3.x (branch `3.x`). See [docs/migrating-from-v3.md](docs/migrating-from-v3.md).

## Installation

Add the gem and install it:

```ruby
gem "active_admin_theme"
```

The gem requires `active_admin` first, so its views and partials win over ActiveAdmin's own. Do not reorder that.

### CSS

ActiveAdmin 4 builds its CSS with Tailwind CSS 4. Your Tailwind entry file (generated by `rails g active_admin:assets`, usually `app/assets/stylesheets/active_admin.css`) must import the theme CSS after Tailwind. Pick one route.

**From the installed gem.** The gem's location differs between machines (a laptop, a Docker image, CI), so the path must not be committed. The task writes it into a generated file next to your entry file, and the entry file only imports that file by a fixed name:

```sh
bin/rails active_admin_theme:css
```

The entry file gets this block, which is the same on every machine, so commit it:

```css
@import "tailwindcss";
@config "../../../tailwind-active_admin.config.js";

/* active_admin_theme:begin */
@import "./active_admin_theme.generated.css";
/* active_admin_theme:end */
```

The task writes `active_admin_theme.generated.css`, which holds the machine-specific path. Add it to `.gitignore`:

```
/app/assets/stylesheets/active_admin_theme.generated.css
```

Run the task before every Tailwind build, because the generated file does not exist on a fresh checkout and its path changes when the gem upgrades. For example, in the build script that runs Tailwind:

```sh
bin/rails active_admin_theme:css && npx tailwindcss -i app/assets/stylesheets/active_admin.css -o app/assets/builds/active_admin.css
```

If that is awkward for your build, use the npm route.

**From the npm package.** This avoids a machine-specific path and a build step, and fits hosts that already install `@activeadmin/activeadmin` from npm:

```sh
npm install @activeadmin-plugins/active_admin_theme
```

```css
@import "tailwindcss";
@config "../../../tailwind-active_admin.config.js";
@import "@activeadmin-plugins/active_admin_theme/css";
```

Keep the npm package and the gem on the same version.

Tailwind only generates the classes it finds in files it scans. In `tailwind-active_admin.config.js`, add the gem's files to `content`:

```js
const themePath = execSync('bundle show active_admin_theme', { encoding: 'utf-8' }).trim().split(/\r?\n/).pop();

export default {
  content: [
    // ActiveAdmin's entries stay as they are
    `${themePath}/app/**/*.{arb,erb,html,rb,js}`,
    `${themePath}/lib/**/*.rb`,
    // ...
  ],
  // ...
}
```

### JavaScript

ActiveAdmin 4 renders its own import map, `ActiveAdmin.importmap`, not the import map in your `config/importmap.rb`. A `pin` in your own `config/importmap.rb` loads nothing on ActiveAdmin pages.

The theme's engine pins its modules into `ActiveAdmin.importmap`, so importmap hosts need no setup. To load one of your own scripts on ActiveAdmin pages, pin it into the same map, for example in `config/initializers/active_admin.rb`:

```ruby
ActiveAdmin.importmap.pin "my_admin_script", to: "my_admin_script.js"
```

ActiveAdmin pages import the modules listed in `ActiveAdminTheme.javascripts`. With an ActiveAdmin that has the `javascript_modules` setting ([activeadmin/activeadmin#9148](https://github.com/activeadmin/activeadmin/pull/9148)), the theme adds them to that setting after your initializers run. With an older ActiveAdmin, the theme's own `_html_head` imports them. The default list is:

```ruby
%w[
  active_admin_theme/layout
  active_admin_theme/server_clock
  active_admin_theme/table_crisscross
  active_admin_theme/searchable_select
]
```

Change the list in an initializer to load fewer scripts or to add the optional ones:

```ruby
ActiveAdminTheme.javascripts -= %w[active_admin_theme/table_crisscross]
ActiveAdminTheme.javascripts += %w[active_admin_theme/secret_reveal]
```

**Your own watched directory.** With an ActiveAdmin that has no `importmap_watches` setting ([activeadmin/activeadmin#9153](https://github.com/activeadmin/activeadmin/pull/9153)) and with `config.importmap.sweep_cache` on, each `ActiveAdmin.importmap.cache_sweeper(watches:)` call replaces the previous watcher. The theme makes that call from an `after_initialize` block that its initializer registers, so it runs after any `config.after_initialize` written in an engine or application class, and replaces that call's watcher. To watch your own directory too, register your block from an initializer that runs after the theme's, and pass every directory:

```ruby
initializer "my_admin.importmap", after: "active_admin_theme.importmap" do |app|
  app.config.after_initialize do
    ActiveAdmin.importmap.cache_sweeper(watches: [
      ActiveAdmin::Engine.root.join("app/javascript"),
      ActiveAdminTheme::Engine.root.join("app/javascript"),
      root.join("app/javascript")
    ].map(&:to_s))
  end
end
```

**jsbundling hosts.** The npm package exports each module (`@activeadmin-plugins/active_admin_theme/layout`, `.../server_clock`, and so on). Import the ones you want from your `active_admin` entry file, and override `app/views/active_admin/_html_head.html.erb` to load your bundle.

## Overriding

A host partial with the same path overrides the theme's. Copy the partial from the gem into your app's `app/views/active_admin/` and edit it. The theme's partials are:

- `_header_leading`: the menu button and the site title.
- `_header_navigation`: the top menu.
- `_main_navigation`: the mobile drawer menu.
- `_header_actions`: the right end of the header. In order: the dark mode switch, the server clock, `_header_links`, the current user, and the logout icon.
- `_header_links`: empty. Override it to add your own links between the clock and the current user.
- `_page_heading`, `_breadcrumbs`, `_page_title`: the breadcrumbs and the page title, on one row of the dark title band. A host copy must keep light text there: use `--aat-titlebar-text` and `--aat-titlebar-muted`.
- `_page_content`: the grid that holds the sidebar and the page, and the tab that collapses the sidebar.
- `_sidebar`.
- `_flash_messages`: the flash bands under the title band.
- `kaminari/*`: the page links under an index table, with "First", "Next ›" and "Last »".

The index footer is one line under the table: per page, page links, the count, and the download links. Its English wording ("Displaying Orders 1 - 30 of 60 in total") comes from the theme's `config/locales/active_admin_theme.en.yml`; your own locale file overrides it, and other languages keep ActiveAdmin's text.

ActiveAdmin renders these partials from its own layout once it has the layout hooks ([activeadmin/activeadmin#9149](https://github.com/activeadmin/activeadmin/pull/9149) to [#9152](https://github.com/activeadmin/activeadmin/pull/9152)). Until then, the theme also ships copies of the layout, `_site_header`, `_page_header`, and `_html_head` in `app/views_compat` that render the same partials. The engine adds that directory to the view paths only when the installed ActiveAdmin lacks the hooks, so override the small partials above rather than those copies.

A host Arbre component with the same builder method name replaces the theme's, as long as it loads after the theme's. Components in `app/admin_components` (or any file loaded in a `to_prepare` block) do.

## Colors

All colors are CSS custom properties with a light value on `:root` and a dark value under `.dark`. Override any of them in your own CSS:

```css
:root {
  --aat-header-bg: #1b3a57;
  --aat-button: #1f6f4a;
}
.dark {
  --aat-surface: #20242b;
}
```

| Property | Used for |
| --- | --- |
| `--aat-page-bg`, `--aat-surface`, `--aat-surface-2`, `--aat-surface-hover`, `--aat-selected-row` | Page, panels, table headers, hover, selected rows |
| `--aat-text`, `--aat-text-muted`, `--aat-border` | Text and borders |
| `--aat-input-bg`, `--aat-input-border` | Form controls |
| `--aat-accent`, `--aat-link` | Accent and links |
| `--aat-button`, `--aat-button-hover`, `--aat-button-text` | Buttons and action items. Every action item is a filled button. |
| `--aat-header-bg`, `--aat-header-text`, `--aat-header-border`, `--aat-menu-*` | Header and top menu |
| `--aat-titlebar-bg`, `--aat-titlebar-text`, `--aat-titlebar-muted` | Title band: background, page title, breadcrumbs. Dark in both modes. |
| `--aat-table-header`, `--aat-filter-label` | Index table header; filter and form field labels |
| `--aat-flash-notice`, `--aat-flash-alert`, `--aat-flash-error`, each with a `-border` variant | Flash band fill and bottom border, the same in both modes |

Two more properties set sizes:

- `--aat-font-size` (default `0.75rem`, 12px) is the base text size of the page, tables, forms, filters, and buttons. Smaller texts, such as filter labels and status tags, scale from it.
- `--aat-label-cap` is the widest the label column of a show page's `attributes_table` gets. The column takes the width of its labels up to the cap; a longer label wraps.

## DSL

### `columns`

ActiveAdmin 4 removed `columns` and `column`. The theme restores them, with separate control for mobile and desktop.

```ruby
columns "1:3" do                 # desktop: 1/4 + 3/4; mobile: stacked
  column { ... }
  column { ... }
end

columns "1:1", mobile: "1:1" do  # side by side on mobile too
  ...
end

columns do                       # no ratio: equal widths, any number of columns
  ...
end
```

- The ratio string lists one weight per column. Pixel widths are not supported.
- On mobile, columns stack unless `mobile:` sets a ratio.
- A column has a minimum width of `--aat-col-min` (14rem). When the row has no room for it, the column moves to the next line instead of clipping its content.
- `column span: N` from ActiveAdmin 3 still works and counts as the column's weight.

### `tabs`

```ruby
tabs do
  tab("Details") { ... }
  tab("History", id: "history") { ... }
end
```

Tabs use Flowbite's tabs, which ActiveAdmin already loads. A tab's panel id is its parameterized title unless `id:` sets it. A title already used on the page gets `-2`, `-3` and so on, and an id that does not start with a letter gets a `tab-` prefix.

### `panel`

ActiveAdmin 4 still has `panel`, but no longer wraps sidebar content or the show page's `attributes_table` in one. The theme wraps both again: sidebar sections in a panel titled with the section name, and `attributes_table` on a show page in a "Model Details" panel. `Panel#header_action` is not restored.

## Components

Every component but the select widget is opt-in: nothing changes for an app that does not call it or load its script. In a `content do` block, wrap the helpers that return strings (`with_tooltip`, `pre_wrap`) in `text_node`.

### `status_tag`

`ok`, `warning`, `error`, `info`, and `empty` have theme colors in light and dark mode. For any other value, define a CSS custom property named `--aat-status-<value>` in your CSS. For a one-off color, pass `color:` (a hex, named, `rgb()`, or `hsl()` color; anything else raises `ArgumentError`):

```ruby
status_tag "Shipped"                # uses --aat-status-shipped, if you define it
status_tag "Late", color: "#b91c1c"
```

Tags are square, small, and shown in uppercase, as in theme 3. The case is CSS only, so the HTML keeps the text you pass, while a browser test driver reads it in uppercase.

### `truncate_text`

One line of text with an ellipsis and the full value in the `title` attribute:

```ruby
truncate_text(order.note, length: 40, max_width: "12rem")
```

With `popup: true` the full value shows in a popup on hover and on keyboard focus, in place of the `title`. The element is focusable and names the popup in `aria-describedby`. The popup is CSS only, and a scrolling table does not clip it:

```ruby
truncate_text(order.note, max_width: "12rem", popup: true)
```

### `with_tooltip`

A plain `title` hint by default. With `html: true`, the tooltip is sanitized HTML shown by ActiveAdmin's Flowbite tooltip. The HTML tooltip is positioned inside its container, so a wrapper with `overflow` (a scrolling table) can clip it.

```ruby
text_node with_tooltip("42", "Total orders")
text_node with_tooltip("42", "<b>Total</b> orders", html: true)
```

### `pre_wrap`

Preformatted text that wraps long lines:

```ruby
text_node pre_wrap(response.body)
```

### `secret_reveal`

A masked value with an eye icon before it. A click fetches and shows the value, and the icon turns to an eye-off icon that hides it again. The URL must return `{"value": "..."}`. Needs the `active_admin_theme/secret_reveal` script.

```ruby
secret_reveal url: secret_admin_account_path(account), mask: "••••••••"
```

### `confirm_dialog`

A confirmation dialog with optional form fields, built on the Flowbite modal that ActiveAdmin uses for batch actions. It submits a real form with the CSRF token. Needs the `active_admin_theme/confirm_dialog` script for focus handling and field validation. Do not place it inside another form.

```ruby
confirm_dialog "Reject", title: "Reject order", message: "The buyer is notified.",
  url: reject_admin_order_path(order), method: :post,
  fields: [
    {name: :reason, label: "Reason", as: :text, required: true},
    {name: :kind, as: :select, collection: [["Fraud", "fraud"], ["Other", "other"]]},
    {name: :notify, label: "Notify the buyer", as: :boolean, value: true}
  ]
```

The dialog has a title bar. Its buttons sit at the left, the confirm button first, then Cancel.

Field types are `:string`, `:text`, `:select`, and `:boolean`. More options:

- `params:` adds hidden fields. Nested hashes and arrays become Rails' bracketed names.
- `class:` adds classes to the button, and `trigger_html:` other attributes. Inside the action items the button looks like the other action items.
- `trigger: false` renders the dialog without a button. It needs `id:`. Any element with `data-modal-target` and `data-modal-show` set to that id opens it; `confirm_dialog_trigger(text, id, **html_options)` renders such a button.

```ruby
confirm_dialog id: "merge", trigger: false, title: "Merge customers?", url: merge_admin_customers_path,
  params: {ids: [3, 4], options: {keep: "newest"}}
text_node confirm_dialog_trigger("Merge", "merge")
```

`confirm_dialog_tag` takes the same arguments and returns HTML, for ERB and for blocks that return a string, such as `action_item`:

```ruby
action_item :reject, only: :show do
  confirm_dialog_tag "Reject", title: "Reject order", url: reject_admin_order_path(resource), class: "action-item-button"
end
```

### Selects

Selects are [Tom Select](https://tom-select.js.org) widgets, drawn by the `active_admin_theme/searchable_select` script. The script is in the default list. The gem vendors a pinned tom-select and pins it into `ActiveAdmin.importmap`; npm hosts add `tom-select` to their own dependencies.

**Every select is upgraded.** Without any setup the script upgrades:

| Select | Widget |
| --- | --- |
| Filter selects (`.filters-form-field.select select`) | Search box in the dropdown, remove button, placeholder "Any" |
| Boolean filters | Remove button, no search box |
| The predicate select of string and numeric filters | No search box |
| Form selects (`form.formtastic li.input.select select`) | Search box in the dropdown; a remove button when the select has a blank option or is multiple |
| `select[data-tom-select]` anywhere | As a form select |

Selects added later, such as `has_many` rows and dialogs, are upgraded when they enter the page. The contents of a `<template>` are left alone.

To turn this off for the whole app, so that only `as: :searchable_select` inputs and selects with `tom_select:` get the widget:

```ruby
ActiveAdminTheme.searchable_select_all = false
```

To drop the script and Tom Select altogether:

```ruby
ActiveAdminTheme.javascripts -= %w[active_admin_theme/searchable_select]
```

**Per-select settings.** `tom_select:` on any select input or filter takes `false` (leave the select native), `true` (upgrade it even when `searchable_select_all` is off) or a hash of [Tom Select settings](https://tom-select.js.org/docs/) merged over the theme's. The hash also takes `addPlugins` and `removePlugins`.

```ruby
f.input :size, as: :select, collection: sizes, tom_select: false
filter :event_eq, as: :select, collection: events, tom_select: {create: true, persist: false} # free-text values
f.input :kind, as: :select, include_blank: "None", tom_select: {allowEmptyOption: true} # the blank option is a row
f.input :tags, as: :select, multiple: true, tom_select: {addPlugins: ["checkbox_options"], removePlugins: ["remove_button"]}
```

The option renders the `data-tom-select` attribute, which you can also write yourself: `"false"`, `"true"` or the settings as JSON.

```ruby
select_tag :color, options_for_select(colors), data: {tom_select: {create: true}}
```

**Settings and texts.** The theme's `_page_content` partial renders them as JSON for the script:

```ruby
ActiveAdminTheme.searchable_select_all = true # upgrade every select
ActiveAdminTheme.searchable_select_min_chars = 3 # characters to type before an AJAX select searches
```

The texts come from I18n, with these defaults:

```yaml
en:
  active_admin_theme:
    searchable_select:
      any: "Any"
      no_results: "No results matched"
      type_to_search: "Type %{count} chars to search..."
      loading: "Loading..."
      loading_more: "Loading more..."
      no_more_results: "No more results"
      select_parent_first: "Select the parent first"
      add: "Add"
```

A host that overrides `_page_content` renders them itself with `<%= active_admin_theme_config_tag %>`. Without that element the script uses the defaults above. A host can also set them in JavaScript, in a script that runs before the theme's script:

```html
<script>window.ActiveAdminTheme = {searchableSelect: {all: false, minChars: 2, texts: {noResults: "Nothing found"}}}</script>
```

The script exports `configure(settings)`, which changes them for selects not upgraded yet, and `upgradeAll(root)`, which upgrades the selects inside a node.

### Searchable select

`as: :searchable_select` is a select that takes its options from an endpoint. The page holds only the selected records. It works in forms and filters, and on mobile.

```ruby
f.input :customer, as: :searchable_select
filter :customer, as: :searchable_select
```

By default it searches once three characters are typed, loads the next page as the dropdown scrolls, and replaces the results when the text changes. Selected items stay. Three spaces ask for the unfiltered list: the length of the raw input counts, and the term is trimmed before it is sent.

| Option | Example | Meaning |
| --- | --- | --- |
| `min_chars:` | `min_chars: 0` | Characters to type before searching. With 0 the first page loads when the select gets focus. |
| `load_all:` | `load_all: true` | Fetch every page up front and filter in the browser. For small collections. |
| `per_page:` | `per_page: 20` | Page size to ask the endpoint for. |
| `placeholder:` | `placeholder: "Search customers"` | Text shown while nothing is selected. |
| `depends_on:` | `depends_on: :country_id` | The input this select depends on: `:country_id` in a form, `:country_id_eq` in a filter. |
| `depends_param:` | `depends_param: "q[region_id_eq]"` | Query param that carries the parent's value, `q[<depends_on>_eq]` by default. |
| `depends_placeholder:` | `depends_placeholder: "Select a country first"` | Text shown while the parent is empty. |
| `resource:` | `resource: Account` | Model or ActiveAdmin resource that has the endpoint, when the input is not an association. |
| `options_name:` | `options_name: :external_id` | Which `searchable_select_options` of the resource to use, `:all` by default. |
| `url:` | `url: -> { all_options_admin_accounts_path }` | The endpoint, as a string or a lambda run in the view. |
| `tom_select:` | `tom_select: {maxItems: 3}` | Tom Select settings for this select. |

**Dependent selects.** A dependent select stays disabled until its parent has a value, and sends that value with every request. When the parent changes or is cleared, the select is cleared and fires `change`, so a select that depends on it resets too. On page load a preselected value is kept, so deep links and submitted filters survive. With `load_all:` the options are fetched again for each parent value.

```ruby
filter :country, as: :searchable_select
filter :city, as: :searchable_select, depends_on: :country_id_eq, depends_placeholder: "Select a country first"
filter :street, as: :searchable_select, depends_on: :city_id_eq, load_all: true
```

**The endpoint.** Declare it in the resource that holds the options:

```ruby
ActiveAdmin.register Customer do
  searchable_select_options
end
```

`searchable_select_options(name = :all, **options)` adds the collection action `<name>_options`, here `GET /admin/customers/all_options`. The name is positional or `name:`. The action checks `authorize!` for reading the resource class, applies the authorization adapter's read scope, and applies `q[...]` params as Ransack filters, which is how a dependent select sends its parent's value.

| Option | Default | Example |
| --- | --- | --- |
| `scope:` | The resource's `scoped_collection` | `scope: -> { Customer.active }`, or with the request params: `scope: ->(params) { Customer.where(kind: params[:kind]) }` |
| `label:` | The first of Formtastic's label methods the record has (`display_name`, `name`, ...) | `label: :email` or `label: ->(customer) { "#{customer.id} | #{customer.name}" }` |
| `search:` | The model's `search(term)` class method or scope when it has one, else `<label column>_cont` | `search: :name_or_email_cont` or `search: ->(scope, term) { scope.search_by_name(term) }` |
| `allow_empty_search:` | `true` | `allow_empty_search: false`: a blank term returns nothing |
| `value:` | `:id` | `value: :external_id`, or a lambda taking the record. An input cannot show the selected record of a lambda. |
| `order:` | Primary key, descending | `order: :name` or `order: ->(scope) { scope.order(:position) }` |
| `per_page:` | `50` | `per_page: 25` |
| `additional_payload:` | none | `additional_payload: ->(customer) { {email: customer.email} }` |

Lambdas run in the resource controller. An unknown option raises `ArgumentError`. The request's `per_page` overrides the page size up to 500, or up to the declared `per_page:` when that is larger.

With `value:` other than the id, name the declaration in the input. The input then finds the selected record by that attribute. A lambda `value:` cannot be looked up, so an input that names such a declaration raises `ArgumentError`:

```ruby
searchable_select_options :external_id, value: :external_id
filter :account_external_id_eq, as: :searchable_select, resource: Account, options_name: :external_id
```

The input looks up the selected records through the same read scope as the endpoint, and through `scope:` when it takes no params. A selected value the user may not read shows the value itself instead of the record's label.

Names from [activeadmin-searchable_select](https://github.com/codevise/activeadmin-searchable_select) and from older hosts also work: `display_text:` for `label:`, `text_attribute:` for `label:` and the searched column, `filter:` for `search:` with a lambda taking `(term, scope)`, and `apply_search:` for `search:` with a lambda taking `(scope, term)`.

**The reply.** The action takes `term`, `page` (starting at 1) and `per_page`, and answers:

```json
{"results": [{"id": 17, "text": "Customer 17"}], "pagination": {"more": true}}
```

This is the shape of activeadmin-searchable_select and select2, except that activeadmin-searchable_select counts pages from 0. An endpoint of your own, given with `url:`, has to answer the same way.

**Your own `searchable_select_options`.** If your app or another gem defines `searchable_select_options` on `ActiveAdmin::ResourceDSL`, that definition wins in any load order, and the theme's inputs need `url:`. To use the theme's instead, prepend it: `ActiveAdmin::ResourceDSL.prepend ActiveAdminTheme::SearchableSelect::ResourceDSL`.

## Nested menus

ActiveAdmin 4 supports one submenu level and raises `TypeError` for a parent chain. The theme brings back the chain from ActiveAdmin 3, so menus can be as deep as you need:

```ruby
menu parent: ["Customer", "Referral Program"], priority: 30
```

In the top menu each deeper level flies out beside its item, and in the drawer it expands below its item. A top item is marked current when the page is anywhere below it.

## Header

The header shows the site title and the top menu, and at its right end the dark mode switch, a server clock, your own links, the current user, and a logout icon. The clock, the user, and the logout icon come from the signed-in user (`current_active_admin_user?`) and `config.logout_link_path`. Without a current user the header shows only the title, the menu, the dark mode switch, and your links. To add links, override `_header_links.html.erb`, which is empty. To change the rest, override `_header_actions.html.erb`, `_header_leading.html.erb`, or `_header_navigation.html.erb`.

## Page objects

The gem ships page objects for system specs, built on [active_admin_page_objects](https://github.com/senid231/active_admin_page_objects) 2.x. The theme never loads them, and does not depend on that gem: add it to your test group and require the entry point from your spec helper.

```ruby
# Gemfile
group :test do
  gem "active_admin_page_objects", github: "senid231/active_admin_page_objects"
end

# spec/rails_helper.rb
require "active_admin_theme/page_objects"
```

The sections of active_admin_page_objects then work on theme pages. Their README describes them; this is what the theme changes and adds. The classes are in `ActiveAdminTheme::PageObjects`.

### Patches to the base sections

- `main_menu` is the top menu on desktop and the drawer on a narrow screen, at any depth. `labels`, `has_item?` and `go` take a label path, and `current_labels` returns one. `click` hovers each parent of the top menu; in the drawer it opens the drawer and each collapsed parent first.
- `ActiveAdminPageObjects::Tabs` drives the theme's `tabs`. Every page has it as `tabs`.
- `form.field(name)` and `filters.filter(name)` return the searchable select classes for an input rendered `as: :searchable_select`. The theme registers them for that wrapper class with `register_field_class` and `register_filter_class`, so a page object that declares the base gem's `SelectField` or `SelectFilter` for such an input raises `DeclaredClassMismatch`.
- The header has no user menu, so `user_menu_button` is never found. Pages get `current_user`, `logout_link`, `server_clock`, `main_menu_button` and `sidebar_toggle` instead.

```ruby
page_object.main_menu.click("Customer", "Referral Program", "Payouts")
page_object.main_menu.labels("Customer", "Referral Program") # => ["Payouts", "Rules"]

show.tabs.titles # => ["Details", "History"]
show.tabs.select("History")
expect(show.tabs).to have_selected("History")
show.tabs.content # the node of the selected tab; content("Details") for another
```

### Sidebar

Every page has `sidebar`. Its sections are panels.

```ruby
index.sidebar.titles # => ["Filters"]
show.sidebar.panel("Help").body
index.collapse_sidebar
index.expand_sidebar
index.sidebar_collapsed?
```

### Selects

The theme prepends a module into `ActiveAdminPageObjects::SelectControl`, so the base gem's `Form::SelectField`, `SelectFilter`, `BooleanFilter` and the predicate select of `StringFilter` and `NumericFilter` pick their option in the Tom Select widget when the select has one, and in the native select when it does not (`tom_select: false`, or `searchable_select_all` off). Reading goes to the `<select>` the widget hides. Specs written for native selects keep working, with a JavaScript driver.

```ruby
form.field(:status).fill("paid") # clicks the widget
form.field(:status).selected # => "paid"
filters.filter(:status).select_option("paid")
filters.filter(:reference).fill_in(with: "ORD", predicate: :start)
```

`SearchableSelectField` and `SearchableSelectFilter` add the widget's own API. `form.field` and `filters.filter` return them for an `as: :searchable_select` input; declare them on a plain select to use that API there: `field :tag, "Tag", ActiveAdminTheme::PageObjects::SearchableSelectField`. They need a JavaScript driver.

Picking in a select that loads its options types the label into the search box first. Pass `search:` to type another text, such as three spaces for the whole list, or `search: false` to type nothing. A plain select types nothing unless `search:` is given.

```ruby
customer = form.field(:customer)
customer.fill("Acme") # choose is the same
customer.fill("Acme", search: "acm")
customer.selected # => "Acme"
customer.chosen # => ["Acme"], every item of a multiple select
customer.remove("Acme") # clear removes every item
customer.placeholder
form.field(:tag).create_option("bulky") # a select with tom_select: {create: true}
expect(form).to have_disabled_field(:city) # a dependent select without its parent

filter = filters.filter(:customer)
filter.select_option("Acme")
expect(filter).to have_item("Acme") # also have_selected and have_disabled
filter.search("ac") # opens the dropdown, types and waits for the reply
filter.message # => "Type 3 chars to search...", or the no-results text
expect(filter).to have_message("No results matched")
expect(filter).to have_option("Acme") # what the open dropdown offers
filter.options # the labels loaded so far
filter.load_more # scrolls to the end, waits for the next page, returns the labels
filter.close
```

A multiple select takes an array in `fill`, and `select_option` once per label.

### Components

A component is found inside any scope: a page, a section, a table cell or an attributes table row.

```ruby
include ActiveAdminTheme::PageObjects

tag = StatusTag.find_in(index.table.row(order.id).cell(:status))
tag.text # => "SHIPPED", as shown; a browser driver reads the uppercase
tag.kind # => "shipped", its data-status
tag.color # => "#b91c1c" with color:, or nil

note = TruncateText.find_in(index.table.row(order.id).cell(:note))
note.text # what the cell shows
note.full_text # the whole value, from the title or the popup
note.popup? # rendered with popup: true
note.show_popup # hovers and returns the popup text
note.cut? # length: cut the text
note.clipped? # CSS clips it to the width; needs a JavaScript driver

secret = SecretReveal.find_in(show.attributes_table.row(:token))
secret.reveal # => "s3cr3t"; raises when the request fails
secret.hide

total = Tooltip.find_in(show.attributes_table.row(:total))
total.tooltip # => "Total orders"

PreWrap.find_in(show.panel("Payload")).lines

row = Columns.find_in(show)
row.weights # => [1, 3]
row.columns.first # a section to look inside

dialog = show.confirm_dialog("Reject") # by the text of its button
dialog.open
dialog.title # => "Reject order"
dialog.fill("Reason" => "Fraud", "Notify the buyer" => true) # by field label
dialog.fill("reason" => "Fraud") # a control of the block body, by its label, id or name
dialog.field("reason")[:"aria-invalid"] # the control itself
dialog.confirm # or cancel
dialog.confirm(validate: false) # skips the browser's required check

merge = show.confirm_dialog(dialog: "merge") # by the id of a dialog with trigger: false
merge.params # => {"ids[]" => "4", "options[keep]" => "newest"}, the hidden fields by name
merge.open # clicks the element of the page that points at the dialog
```

`all_in(scope)` returns every such component in the scope.

## Development

```sh
bundle install
bundle exec rake test                 # builds the dummy app's Tailwind CSS, runs smoke and browser tests (needs Chrome)
bundle exec ruby test/screenshot.rb   # PAGES, WIDTHS, MODES, OUT environment variables
```

`test/dummy` is an ActiveAdmin 4 app (importmap, propshaft, Tailwind through the npm CLI). Run `npm run build` in `test/dummy` to rebuild its CSS.

To run the tests against an unreleased ActiveAdmin, such as a branch with the layout hooks, point Bundler at it:

```sh
ACTIVEADMIN_PATH=../activeadmin bundle exec rake test
ACTIVEADMIN_BRANCH=extensible-layout bundle exec rake test   # from ACTIVEADMIN_REPO, default senid231/activeadmin
```

The theme replaces some of ActiveAdmin's own view files with its copies. `test/aa_overrides_test.rb` fails when the installed ActiveAdmin changes one of them. It records the originals for both modes, with and without the layout hooks, so run it against both. After you raise the ActiveAdmin version, diff each reported file against the theme's copy in `app/views` or `app/views_compat`, port what applies, then refresh the record:

```sh
UPDATE_AA_DIGESTS=1 bundle exec ruby test/aa_overrides_test.rb
```
